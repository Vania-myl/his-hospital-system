## 2. 全局开发约定

### 2.1 分层架构
```
Vue 页面 → Controller → Service(接口/Impl) → Mapper → MySQL
```
- 表现层（Controller）：只做参数校验、路由转发、返回 JSON，**不写业务逻辑**。
- 业务逻辑层（Service + ServiceImpl）：封装业务规则、事务控制、异常。
- 数据访问层（Mapper + XML）：MyBatis 半自动 ORM。
- 实体 Entity 与 DTO 作为层间数据载体。

### 2.2 命名规范
- 数据库：表名、字段名 **snake_case**（小写英文 + 下划线）。
- Java：类、方法、变量 **驼峰命名**。
- 主键统一 `id`；逻辑外键统一 `xxx_id`；软删除标记统一 `delmark`。
- 用例编号 `UC-` 前缀、业务规则 `BR-` 前缀、非功能需求 `NFR-` 前缀。

### 2.3 统一返回体（所有接口必须遵守）
```json
{ "code": 200, "msg": "success", "data": {} }
```
- 通用返回类 `Result<T>`：`success()` / `error()` / `data()`。

### 2.4 状态码与错误码
| code | 含义 |
| --- | --- |
| 200 | 成功 |
| 400 | 参数错误 / 校验失败 |
| 401 | 未登录或 token 失效 |
| 403 | 无权限访问 |
| 500 | 服务器内部错误 |
| 1001 | 该医生号源已满 |
| 1002 | 患者已就诊，不可退号 |
| 1003 | 项目已执行 / 已取药，不可退费 |
| 1004 | 用户名或密码错误 |

### 2.5 鉴权与权限
- 登录返回 JWT token，前端请求头携带 `Authorization: Bearer <token>`。
- 后端拦截器统一校验 token 与角色；白名单：登录、退出等。
- RBAC 按 `employee.role` 实现最小权限，前端菜单只控制显示，**后端必须再次鉴权**。

### 2.6 数据一致性
- 表间**逻辑外键**（`xxx_id`），不建物理 FOREIGN KEY，引用完整性由 Service 层事务保证。
- 挂号、退号、收费、退费、发药等核心写操作标 `@Transactional`。
- 基础数据表统一 `delmark INT(1) DEFAULT 1`（1-正常 0-已删除），**软删除**。
- 金额统一 `DECIMAL(8,2)`；时间统一 `DATETIME`。
- 业务关键字段 `NOT NULL`；身份证、住址、备注、退费关联可空。

检查列表参数：`caseNumber`（精确）、`realName`（模糊）、`checkState`（1~4）、`creationDate`（yyyy-MM-dd）、`page`（默认 1）、`size`（默认 10，最多 100）。响应 `data` 为 `{ records, total, page, size }`，每条记录的 `paymentReady` 为 1（已收费未退）或 0（未收费/已退）。`assign` 无请求体；`result` 请求体为 `{ checkResult, checkRemark }`，结果必填，均不超过 512 字。仅 `check` 角色可访问；登记要求状态 1 且已收费未退费，更新为 2；录入结果要求状态 2，更新为 3。操作人和操作时间由后端写入。

## 5. 模块归属与边界

| 成员 | 模块 | 负责表 | 接口 |
| --- | --- | --- | --- |
| MYL | 挂号收费 + 综合管理 + 公共基础 | employee、department、regist_level、settle_category、scheduling、register、fee_record | 4.1 + 4.2 + 4.3 |
| WWJ | 门诊医生 + 药房管理 | medical_record、medical_record_disease、disease、prescription、drug_info | 4.4 + 4.8 |
| HYJ | 检查 + 检验 + 处置管理 | check_request、inspection_request、disposal_request、medical_technology | 4.5 + 4.6 + 4.7 |

**跨模块依赖提示：**
- `register`、`fee_record` 是 MYL 负责，但下游门诊医生、药房、综合管理都要**读**它们——写由 MYL 负责，其他人只读。
- `medical_technology`（医技项目）被门诊医生（开申请时选项目）和检查/检验/处置（执行时）共用，HYJ 负责维护，WWJ 读。
- 检查、检验、处置申请表的 Mapper 由 HYJ 维护，提供 `insert` / `selectById` 供 WWJ 的开立与详情业务调用；WWJ 负责其 Controller 与 Service，不重复建立同名 Mapper/XML。
- 基础数据（department、regist_level、settle_category、employee）由 MYL 先建好并灌入初始数据，全组共用。
